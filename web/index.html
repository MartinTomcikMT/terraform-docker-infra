Azure Entra ID Cloud identity provider for users, groups, applications and service principals.
Identity

What it does

Azure Entra ID is a cloud identity provider for users, groups, applications and service principals. It handles sign-in, SSO, MFA, Conditional Access and identities outside virtual machines or servers.

When it is used

It is used to control who or what can authenticate to Azure and enterprise applications. It is the foundation for app registrations, service principals and managed identities.

Remember

  • A tenant is an identity boundary.
  • Authentication verifies who you are; authorization defines what you can do.
  • A service principal is an application or automation identity.
  • Managed identity removes the need to manually store and rotate secrets.

Possible interview questions

  • What is the difference between Entra ID and Azure RBAC?
  • What is a service principal and where is it used?
  • Why is managed identity safer than a stored client secret?
  • What does Conditional Access solve?
Azure RBAC Role-Based Access Control for Azure resources.
Access control

What it does

Azure RBAC defines permissions for Azure resources. Roles are assigned at a scope such as a management group, subscription, resource group or individual resource.

When it is used

It is used to apply least privilege. For example, a developer can be Reader in production, Contributor in a development resource group and a pipeline can deploy only to selected resources.

Remember

  • Permissions are inherited down the scope hierarchy.
  • Common built-in roles are Owner, Contributor, Reader and User Access Administrator.
  • Custom roles allow more precise permissions.
  • RBAC is not the same as network rules.

Possible interview questions

  • How would you allow a pipeline to deploy only to one resource group?
  • What is the difference between Owner and Contributor?
  • What does least privilege mean?
  • How does inheritance work in Azure RBAC?
Management Groups / Subscriptions / Resource Groups Azure hierarchy for governance, billing, policy and resource organization.
Governance

What it does

This is the hierarchy used to organize Azure environments. Management groups contain subscriptions, a subscription is a billing and isolation boundary, and a resource group is a logical container for resources.

When it is used

It is used for organizing environments, billing, policy, RBAC and resource lifecycle. Common patterns include separate development, test and production subscriptions.

Remember

  • A resource group has a region, but it can contain resources from multiple regions.
  • Policy and RBAC can be applied higher in the hierarchy.
  • Subscriptions have quotas and limits.
  • Deleting a resource group deletes the resources inside it.

Possible interview questions

  • When should environments be split into multiple subscriptions?
  • What is a resource group and why is it important?
  • What is the difference between a subscription and a tenant?
  • How would you organize dev, test and production?
Azure Policy Governance service for enforcing rules on Azure resources.
Governance

What it does

Azure Policy enforces rules over Azure resources. It can audit, deny or modify unwanted configurations such as missing tags, disallowed regions or public IP usage.

When it is used

It is used for compliance, standardization and guardrails. It helps ensure that teams deploy resources according to company rules.

Remember

  • A policy can audit, deny or modify.
  • An initiative is a group of policies.
  • Policy is not a replacement for monitoring or RBAC.
  • It works well together with management groups.

Possible interview questions

  • How would you require every resource to have an owner tag?
  • What is the difference between Azure Policy and RBAC?
  • What is a policy initiative?
  • What happens when a deny policy is triggered?
Azure Virtual Network Private network in Azure for segmentation, routing and private connectivity.
Networking

What it does

Azure Virtual Network is a private network in Azure. It contains address spaces, subnets, route tables, DNS settings and connects resources such as VMs, AKS and private endpoints.

When it is used

It is used for isolation and traffic control. It is the foundation for hybrid connectivity, segmentation and private access to PaaS services.

Remember

  • A subnet is part of a VNet address range.
  • VNet peering connects Azure networks.
  • CIDR ranges must not overlap when peering or connecting hybrid networks.
  • NSG controls traffic at subnet or NIC level.

Possible interview questions

  • What is a subnet and why is it used?
  • How do you connect two VNets?
  • Why is overlapping CIDR a problem?
  • What is the difference between a VNet and a subnet?
Network Security Group Stateful firewall rules for inbound and outbound traffic in Azure.
Networking

What it does

A Network Security Group is a stateful set of firewall rules for inbound and outbound traffic at subnet or network interface level.

When it is used

It is used to allow or block traffic between subnets, virtual machines and the internet. A common example is allowing SSH or RDP only from an admin IP range.

Remember

  • Rules have priorities; lower numbers are evaluated first.
  • NSG is stateful, so return traffic for an allowed connection is automatically allowed.
  • Default rules always exist.
  • NSG is not a Layer 7 firewall.

Possible interview questions

  • How would you allow SSH only from one IP address?
  • What does priority mean in NSG rules?
  • What is the difference between NSG and Azure Firewall?
  • Is NSG stateful or stateless?

Security / Networking

What it does

Azure Firewall is a managed network firewall for centralized protection. It supports network rules, application rules, NAT rules, threat intelligence and logging.

When it is used

It is commonly used in hub-and-spoke network architectures to control ingress and egress traffic, centralize logs and apply security rules consistently.

Remember

  • It is useful for centralized traffic control.
  • It supports FQDN rules for outbound HTTP/S traffic.
  • It is often combined with route tables.
  • It is not the same as an NSG.

Possible interview questions

  • When would you use Azure Firewall instead of NSG?
  • What is a hub-and-spoke network architecture?
  • How do you force subnet traffic through a firewall?
  • What are application rules?
VPN Gateway / ExpressRoute Hybrid connectivity between on-premises networks and Azure.
Hybrid networking

What it does

VPN Gateway connects an on-premises network to Azure through an encrypted tunnel over the internet. ExpressRoute provides private dedicated connectivity outside the public internet.

When it is used

VPN is often cheaper and faster to set up. ExpressRoute is used for enterprise hybrid scenarios that require higher stability, throughput and predictable connectivity.

Remember

  • VPN uses an IPsec tunnel.
  • ExpressRoute is not an internet VPN.
  • GatewaySubnet is a special subnet for the gateway.
  • BGP is often used for dynamic routing.

Possible interview questions

  • What is BGP?

Private access

What it does

A Private Endpoint gives a PaaS service a private IP address inside a VNet. Private Link enables private access to a service without using the public internet.

When it is used

It is used when services such as Storage, SQL, Key Vault or other PaaS services should not be publicly reachable.

Remember

  • A private endpoint is a network interface with a private IP address.
  • DNS is critical; otherwise clients may still resolve the public endpoint.
  • Public network access is often disabled.
  • NSG and routing behavior depends on the service configuration.

Possible interview questions

  • Why must DNS be handled after creating a private endpoint?
  • How do you disable public access to a Storage Account?
  • What is the difference between service endpoint and private endpoint?
  • What is Private Link?
Azure Load Balancer Layer 4 load balancer for TCP and UDP traffic.
Load balancing

What it does

Azure Load Balancer is a Layer 4 load balancer for TCP and UDP traffic. It distributes traffic across backend instances such as VMs or VM Scale Sets.

When it is used

It is used for simple Layer 4 balancing, inbound NAT rules and internal or public load balancing scenarios.

Remember

  • It works at Layer 4, not at HTTP path-routing level.
  • Health probes determine backend health.
  • It can be public or internal.
  • For Layer 7 HTTP routing, Application Gateway or Front Door is usually better.

Possible interview questions

  • What is the difference between Azure Load Balancer and Application Gateway?
  • What is a health probe?
  • When would you use an internal load balancer?
  • Which OSI layer does it operate on?
Application Gateway + WAF Layer 7 application delivery with HTTP routing and web protection.
Application delivery

What it does

Application Gateway is a Layer 7 load balancer for HTTP/S applications. It supports TLS termination, host and path-based routing, cookie affinity and Web Application Firewall.

When it is used

It is used for web applications that need URL-based routing, HTTPS offload or protection against common web attacks.

Remember

  • It works at Layer 7.
  • WAF protects against common web attacks such as OWASP Top 10 patterns.
  • The backend pool can contain VMs, App Service or AKS ingress targets.
  • Listener, rule, backend pool and probe are core configuration parts.

Possible interview questions

  • When would you use Application Gateway instead of Load Balancer?
  • What does WAF do?
  • What is TLS termination?
  • How does path-based routing work?
Azure Front Door / Traffic Manager Global routing, acceleration and failover for applications.
Global routing

What it does

Azure Front Door is a global Layer 7 entry point with routing, TLS, acceleration and WAF. Traffic Manager is DNS-based traffic routing by priority, performance or geography.

When it is used

Front Door is useful for global web applications. Traffic Manager is useful for DNS failover or geographic routing.

Remember

  • Front Door proxies HTTP/S traffic.
  • Traffic Manager returns DNS answers and is not a proxy.
  • Front Door supports WAF.
  • DNS TTL affects failover speed with Traffic Manager.

Possible interview questions

  • What is the difference between Front Door and Traffic Manager?
  • Which service works through DNS?
  • How would you design global failover for a web application?
  • Where would you enable WAF?
